## real_estate_intelligence/real_estate_intelligence/agent/EGM.md

- **[Blocker]** Invariants, key resolution order claim [copilot.py:run_query] — Contract states "if the explicit key starts with `\"sk-\"` or env `OPENAI_API_KEY` is set, the OpenAI loop is used instead." Actual code in `real_estate_intelligence/real_estate_intelligence/agent/copilot.py:224-232` (`AgenticCopilot.run_query`): `key = api_key or os.environ.get("GEMINI_API_KEY") or os.environ.get("GOOGLE_API_KEY")`; any truthy `api_key` — including one starting with `"sk-"` — is passed directly to `_run_gemini_loop` and sent to the Gemini endpoint. The `sk-` branch at line 227 (`api_key if (api_key and api_key.startswith("sk-")) else os.environ.get("OPENAI_API_KEY")`) is dead code for explicit keys: it is only reachable when `key` is falsy, which requires `api_key` to be falsy, so the `sk-` test can never succeed. The OpenAI loop therefore runs only when no Gemini-family key is resolvable AND env `OPENAI_API_KEY` is set (and even then, if `GEMINI_API_KEY`/`GOOGLE_API_KEY` are also set, Gemini wins). The documented routing of explicit `sk-` keys to OpenAI does not exist in the source.
